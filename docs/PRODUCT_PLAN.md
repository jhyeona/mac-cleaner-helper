# 비우(Biu) 제품 계획과 구현 현황

## 제품 약속

비우는 사용자가 Mac의 저장 공간을 이해하고, 삭제의 영향을 확인한 뒤,
복구 가능한 방식으로 정리하도록 돕는다. 단순히 큰 숫자를 보여주는 것보다
`왜 큰지`, `지워도 되는지`, `무슨 일이 생기는지`를 설명하는 것이 우선이다.

## 구현 현황

1. **분석기** — 여러 폴더, 스트리밍 결과·진행률, 취소, 두 종류의 크기와 오류 구분을 구현했다.
2. **탐지 팩** — 주요 개발 생태계와 IDE 캐시 규칙, 안전한 사용자 규칙 타입을 구현했다.
3. **정리 엔진** — 휴지통, 제한된 캐시 삭제, 공식 CLI, 사전 재검증과 SwiftData 기록을 구현했다.
4. **비우 경험** — 8개 상태, 로컬 문구, 모션 감소, 선택형 플로팅 패널과 조용한 모드를 구현했다.
5. **제품 UI** — 온보딩, 필터·검색, 상세 영향, 정리 바구니, 최종 확인과 기록 관리를 구현했다.
6. **배포 준비** — 로컬 동작 원칙은 반영했으며 서명·공증·Sparkle 피드는 RC 작업으로 남아 있다.

## 삭제 안전 원칙

- 분석과 삭제는 분리한다.
- 사용자가 선택하지 않은 위치는 스캔하지 않는다.
- 시스템 및 개인 원본 데이터는 자동 선택하지 않는다.
- 기본 삭제 수단은 휴지통 이동이다.
- 예상 확보 용량과 실제 확보 용량을 구분한다.
- 판단 근거가 부족하면 항상 `확인 필요`로 낮춘다.
- 앱 이름이 아니라 실제 경로와 영향 설명을 함께 보여준다.

## 현재 완료 기준

- 사용자가 여러 폴더를 등록해 분석할 수 있다.
- 크기가 큰 항목부터 정렬된다.
- 항목마다 안전도, 판단 근거, 예상 영향을 볼 수 있다.
- 모든 항목은 기본 선택되지 않으며 보호 대상은 선택할 수 없다.
- 선택 항목은 휴지통으로만 이동한다.
- 부분 성공을 포함한 작업 결과와 실패 이유를 각각 기록한다.

## RC 전 검증

- 10만 파일, 희소 파일, 외장 디스크와 권한 제한 환경의 성능 계측
- 휴지통, 공식 CLI, 실행 직전 대상 변경을 실제 백업 환경에서 통합 검증
- VoiceOver, 키보드 전용 조작, 다중 디스플레이와 전체 화면 앱 UI 테스트
- Developer ID, Hardened Runtime, 공증과 Sparkle 2 업데이트 피드 구성
